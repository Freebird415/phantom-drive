# 项目整理规范

> **触发方式**：用户说"做一次项目整理 / 全面检查 / 收工前整理"时，按本文件执行。
> **目标**：脚本无缺陷、文档无矛盾、文件摆放正确、正向文档无返工噪声。
> 最后更新：**2026-10-01**（四个 .bat 含蓝牙日志.bat；新增 §0 不确定性与仓库检查命令）

---

## 一、四个检查维度

### 1. 脚本检查（根目录四个 `.bat`：`拉取.bat` / `提交.bat` / `面板.bat` / `蓝牙日志.bat`）

| 检查项 | 判据 |
|---|---|
| 编码 | 必须是 **GBK**（含中文的 UTF-8 .bat 会让 cmd 解析错位） |
| 换行 | 必须**全部 CRLF**，不允许裸 LF（混用同样会让 cmd 解析错位） |
| 结构 | 保留必要元素：`cd /d "%~dp0"`、基线 `chcp 936`、需要显示 git 输出的段落用 `chcp 65001` 包裹、结尾 `pause` |
| 逻辑 | **任何改动后必须在沙盒实测**，不实测不算完成 |

**沙盒实测方法（四条经验）**：
1. 建一个"裸仓库 + 克隆"的临时环境，把脚本放进去跑
2. 把 `set /p` 输入行替换成固定值（如 `set act=1`）来驱动流程
3. 测试脚本必须**提交并推送到沙盒远端**——若测试脚本处于"未跟踪"或"已修改"状态，`reset --hard` / `git clean` 会删除或还原它，造成假故障
4. 用管道喂多行输入会让 `set /p` 吞掉整段内容（测试假象，不是脚本 bug）

### 2. 一致性检查

- **任务一致性**：13 个任务号（D01 P01 P02 F01 · H01 H02 · A01 A02 · M01 M02 · D02 · S01 S02）在以下位置必须一致：
  - `项目记录/开发记录.md`：§3.1 任务详情、§3.2 交接时间线
  - `计划和任务/任务清单.md`（与同名 PDF 同内容）：§2 分工总览、§3 任务详情、§4 交接时间线、§7 进度看板
  - `README.md` 结构表的"相关任务"列；`说明书.md` 组规里的目录归属
  - `计划和任务/任务清单.md` 与 PDF 为同一份数据，改动后重跑 `python 生成任务清单.py --build`；不得与实际冲突
- **DDL 一致性**：§3.1 的 DDL、§3.2 的交接时间、§8 里程碑，三处对同一件事的表述必须一致
- **链接完整性**：所有 md 里的相对链接必须真实存在
- **台账与看板不得矛盾**：`项目记录/实际进度.md` 里的事实，与 `开发记录.md` §7 进度看板的状态必须一致（同一件事不能一处写“已交付”、一处写“未开始”）；已拍板结论以 `项目记录/决策登记.md` 为准，三者不得互相矛盾
- **冻结日与现状不得矛盾**：已提前完成的节点（如《引脚分配表》9/23 冻结、PCB 9/30 到货），计划类文档要么标“实际已完成”，要么不在正文里留着过时的“待办”措辞
- **无残留**：不得出现已废弃的名字（`开发册`、`经验.md`、`test.md`、`提交操作/`、旧脚本名、老任务编号 `C0/C1/C2/C3`、`原理图草案/`（现名 `电气设计/`）、`车架与PCB对接约定.md`（该交付物已取消）等）——检查时**跳过本文件**（这里列出的废弃名就是用来对照的）。
  **例外**：`经验与踩坑.md`、`实际进度.md` 里**明确标注为历史演进**的条目可以保留旧名（那两处的职责就是保留过程）；`决策登记.md` 与所有正向文档里出现旧名 = FAIL（台账必须写当前名字）

### 3. 文件摆放

- **根目录白名单**：`README.md`、`说明书.md`、`AGENTS.md`、`拉取.bat`、`提交.bat`、`面板.bat`、`蓝牙日志.bat`（日志摘要放 `logs/共享_*.md`，见 `logs/README.md`）、`.gitignore`、`.gitattributes`、`项目记录/`、`计划和任务/`、`docs/`、`firmware/`、`hardware/`、`mech/`、`tools/`、`报销/`、`参考资料/`、`logs/`（本地实验日志，不入库）
- 工作目录（firmware / hardware / mech / tools）未开工时只应有占位 `README.md`
- **每个工作目录的 `README.md` 必须写清三件事**：该目录的要求/红线、交付物与时间、存放约定（资料放哪、什么不放仓库）
- 临时产物一律放 `参考资料/临时解析文件/`，或直接删除
- **`logs/` 是数据区**：除工具生成的 `共享_*.md`，任何脚本/智能体**不得往里写文件**（验证规则请用临时目录）✓
- **日志统一放 `logs/`**：完整 CSV 不入库（`.gitignore` 拦 ✓），**只放行 `共享_*.md` 摘要**（每份 3~6KB，入库 ✓）—— 见 `logs/README.md`
- **不得混入工具目录**：智能体工具私有目录（`.reasonix/`、`.codebuddy/`、`.cursor/`、`.claude/` 等）与 Python 缓存（`__pycache__/`、`*.pyc`）必须被 `.gitignore` 覆盖；若已经被提交过，用 `git rm -r --cached <目录>` 移除并补进 `.gitignore`

### 4. 降噪（本规范的核心）

**正向文档** = `README.md`、`AGENTS.md`、`说明书.md`、`docs/*`、`项目记录/开发记录.md`。
它们**只写"现在应该怎么做"**，禁止出现：

- ❌ "原来做了 X，后来改成 Y"、"曾考虑…最终决定…"、"用户要求不要…"
- ❌ 修复 / 返工过程的叙述（"加固了…"、"重构了…"、"把 A 改成 B"）
- ❌ 变更记录里的琐碎迭代（只保留里程碑级；细节迭代属于《经验与踩坑》）
- ✅ 合法例外：文件名本身含这些词（《经验与踩坑》）、规则文本在讲"要避免这些词"、原文引用（如规则里的"一票否决"）

发现噪声 → 搬去（或直接删，若已过时）`项目记录/经验与踩坑.md`。

## 二、检查命令（可直接跑）

```bash
# 1) 脚本编码与换行（应：GBK 可解码、裸 LF = 0）
python -c "
import io
for f in ['拉取.bat','提交.bat','面板.bat','蓝牙日志.bat']:
    d = io.open(f,'rb').read()
    crlf = d.count(b'\r\n'); lf = d.count(b'\n') - crlf
    try: d.decode('gbk'); enc = 'GBK OK'
    except Exception: enc = '编码异常'
    print(f, '| CRLF:', crlf, '| 裸LF:', lf, '|', enc)
"

# 2) 旧名残留（应输出为空）
grep -rn "开发册\|经验\.md\|test\.md\|提交操作" --include="*.md" --include="*.bat" .

# 3) 失效链接：逐个 md 解析其中的 markdown 链接，验证目标文件真实存在
# 4) 任务号出现次数（13 个号都应 >0，且各文档一致）
grep -c "D01\|P01\|P02\|F01\|H01\|H02\|A01\|A02\|M01\|M02\|D02\|S01\|S02" 项目记录/开发记录.md README.md 说明书.md
```

## 三、整理产出要求

1. 发现的问题要**修掉**，不能只报告
2. 修完**重跑检查**，确认全绿
3. 汇报时按维度给出：**通过项 / 修复项 / 遗留项**
4. **不要自动提交**——按 `AGENTS.md` 硬规则，提交需用户确认
