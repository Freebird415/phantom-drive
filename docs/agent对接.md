## 一、给组员：让智能体三分钟进入状态

### 1.0 第 0 步：先告诉智能体「你是谁」

智能体动手前**必须先问一句**：

> **你是组长（李沛阳）还是组员？**

| 身份 | 可改范围 |
|---|---|
| **组长** | 仓库里**任何文件**都可以改（包括下面的“规范文件”） |
| **组员** | **禁止修改规范文件**（`AGENTS.md`、`README.md`、`说明书.md`、`docs/`、`.gitignore`、`.gitattributes`、`.bat` 脚本，清单见 §四 第 9 条）—— 需要改就先在群里说，由组长处理 |

> 组员请主动回答身份（也可以直接在第一句话里说明任务号 + 身份），别让 agent 猜。猜错的后果是白干活：改了规范文件的提交会被拦下来。

### 1.1 三步开场

1. 在**仓库根目录**打开智能体（它会自动读 `AGENTS.md`——那是项目的导航 + 硬规则）
2. 第一句话建议这么说：
   > 读一下 `AGENTS.md` 导航里的文件，告诉我：我负责哪些任务、现在该做什么。
3. 之后每次开新任务，先说清三件事：**我是谁（任务号）**、**要做什么**、**做完给谁**

### 1.2 提示词模板（可直接抄）

| 场景 | 建议说法 |
|---|---|
| 找任务 | 我负责任务 H02，读 `项目记录/开发记录.md` 的 3.1、3.2、3.3，告诉我交付物、DDL 和上下游 |
| 技术活 | 按 `docs/技术约定.md` 检查我这份接线/代码方案有没有违反红线 |
| 排障 | 读 `项目记录/经验与踩坑.md`，看有没有和这个现象相关的坑 |
| **分析跑车日志** | 读 `docs/agent对接.md`「三·补一：怎么读日志」；日志目录里**先读 `note.md`**（自描述+汇总），再读 `derived.csv`（已算好的派生量）|
| **上场跑车** | 读 `项目记录/比赛日操作卡.md`（发车动作 / 终点 / 合规红线，按比赛规则原文整理）|

### 1.3 三条纪律（用智能体的组员请记住）

1. **智能体不能替代实测**：调参、装车、跑赛道必须人来做（分工里写明的"含实测调参"就是指这个）
2. **提交前你自己过一眼**：用一键脚本提交；agent 改了什么、提交信息是什么，由你负责
3. **别把不该给的东西喂给外部服务**：发票、个人信息、账号密码不要粘给 AI
4. **agent 越界要拦下**：如果 agent 改了 `AGENTS.md`、`说明书.md`、`README.md`、`docs/` 或 `.bat` 脚本（`拉取.bat`／`提交.bat`／`面板.bat`／`蓝牙日志.bat`），**先别提交**，在群里说一声——这些是组长维护的“规范文件”；`项目记录/` 才是大家都能改的共享区

### 1.4 让 AI「直接读仓库」的两种方式（2026-09-13 实测）

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **A. 本地克隆**（能力最全） | 克隆仓库后，在仓库目录里打开智能体（pi / reasonix / ChatGPT 桌面版的编码模式…） | 要**改代码、跑脚本、提交** |
| **B. ChatGPT GitHub 连接器** | ChatGPT → 设置 → 插件 → 浏览目录 → GitHub → 连接（用**自己的** GitHub 账号授权） | 只想**问答式读代码/文档** |

**连接器要点**：
1. **不需要仓库所有者额外配置，协作者也能用** —— 它走「用户级授权」（GitHub 侧显示在 `Settings → Applications → Authorized GitHub Apps` 的 `ChatGPT Codex Connector`），访问范围 = **你自己账号对仓库的权限**
2. **提问要给文件名/路径**：仓库选择器只搜仓库名、不搜文件内容 → 说「读 `docs/遥测协议.md`」而不是「读一下我的仓库」
3. **它是按需检索**：ChatGPT 把搜索词发给 GitHub、只取相关片段，不会把整个仓库灌进上下文
4. **额度分两套**：普通聊天走套餐的「聊天额度」；编码/agent 模式（读本地文件夹、动代码）走另一套 Work/agent 额度，消耗快得多 → 只想「看懂代码」就用聊天＋连接器，要「动手改」才用 agent 模式
5. 新仓库出现在列表里可能有 **约 5 分钟**延迟

> 连接器能看到的是**整个仓库**（无法只授权子目录）——所以发票、个人信息别往仓库里放（见 §1.3）。

## 三·补一：怎么读日志（无线链路 —— 跑车时的主链路）

> 车在地上/赛道上时插不了串口 ⇒ **数据靠车载蓝牙回传**。三种场合各走各的路：

| 场合 | 怎么做 | 拿到什么 |
|---|---|---|
| 车在跑（插不了线）| 双击根目录「**蓝牙日志.bat**」→ 点「开始接收」→ 跑车，看到关键处**按空格**打关键帧 → 停止 | `logs/<时间>_<备注>/telemetry.csv`（约 33 帧/s）|
| 只想看某一段 | 「保存日志…」→ 选 **[自动定位有效段]** 或 关键帧/帧号 → **起个名字** → 导出 | 一个**独立子目录**（下面是三份文件）|
| 车收回来、要 100Hz 全精度 | 插线 → `DUMP`（或 `tools/snapshot.py`）| 板载快照（掉电不丢）|

**日志是嵌套树**：片段建在母日志里（`<母日志>/片段_<名字>/`），所以在片段上再截就是二级片段 ✓

### 三份文件怎么用

| 文件 | 里面是什么 | 用法 |
|---|---|---|
| `telemetry.csv` | 逐帧原始遥测（与 `$T` 同一套字段）| `python tools/plot.py <目录>` 直接出图 |
| **`derived.csv`** | **已经算好的派生量**：`mm_l/mm_r`、`speed_mm_s`、`yaw_enc_dps`、`gyro_dps`、`turn`/`turn_src`、`moving` | **让 AI 直接读它**，不必自己重算（省 token ✓）|
| `note.md` | 自描述：来源 / 范围 / 帧数 + **汇总统计**（里程、均速峰速、左转右转帧数、陀螺仪与编码器各自累计转角、gz 是否在报数）+ 每列含义 + 关键帧列表 | **先读这个**，一眼知道这段是什么 |

### 三条必须知道的读法约定（都是踩过的坑）

1. **BLE 每帧只是 10ms 的增量**（固件每 3 个采样才发 1 帧）⇒ 自己按行累加时**要 ×3**；`note.md` 的汇总**已自动 ×3** ✓
2. **`state` 状态码**：0 = 丢线/待机 · 1 = 循迹 · **5 = 起步找线** · 4 = 精停
3. **转向看陀螺仪、距离看编码器**：同一段数据里“陀螺仪累计转角”是“编码器差速积分”的 **3.27 倍**（现象确凿，**真因未分辨**：
   疑为转向横向打滑，也可能是轮距取值/编码器丢脉冲/陀螺零偏 —— 见 `经验与踩坑.md` ㊿）。
   实践上：姿态优先信陀螺仪（注意它有零偏），**距离/速度仍以编码器为准**（陀螺仪不测位移）

### 真假数据判据

真数据 `|err| ≤ 3.5`（8 路加权平均的物理极限）；**出现 ±5.0 就是模拟数据**。
灰度不在线时固件把 `allow_drive` 置 0（**绝不驱动电机**）、每 500ms 重探，`TRACE` 回包会打印灰度状态。

## 三·补二：常用命令卡（插线时用；跑车时不要发任何命令 = 规则要求全自动）

| 命令 | 作用 |
|---|---|
| `GET` | 参数（`$P,ms,kp,ki,kd,base_speed`）|
| `TRACE 0\|1` | 只算不发 / 真的发车（台面用；**赛场用 PA12 长按**）|
| `FINSTAT` / `FINRESET` / `STOPDIST <mm>` | 精停状态 / 复位 / 最后一段距离（默认 80mm）|
| `SEEK 0\|1` | 起步找线开关（调试）|
| `ENC` / `ENCRESET` | 编码器计数 / 清零 |
| `MPU` / `MPUINIT` | 陀螺仪读数与健康度 / 手动重新初始化（芯片睡回去时固件会自动重试）|
| `DUMP` / `SNAPFLASH` | 读板载快照 / 看 Flash 里的快照信息 |
| `SNAP 1` / `SNAP 0` | 开始 / 停止记录 |
| `BTL 0\|1` | 无线回传开关（上电默认开；发车按键也会开）|
| `SET <名> <值>` | 在线改参数（`SET kp 8`；**断电会丢**，定稿要写回固件默认值）|


## 四、智能体行为规范（本项目特有）

1. **先确认身份**：动手前先问清对方是**组长还是组员**。**组员** → 禁改规范文件（清单见第 9 条）；要改先报告组长。**组长** → 无此限制
2. **提交必须经用户确认**：不要自作主张 `commit` / `push`；改完停下汇报，等用户说“提交”（完整流程与冲突处理见项目根目录 `AGENTS.md` 硬规则 2）
3. **文档同步**：完成活后按 `docs/文档维护.md` 更新 `项目记录/开发记录.md`（正向）与 `项目记录/经验与踩坑.md`（踩坑/试错）
4. **降噪**：正向文档只写"现在应该怎么做"，不写"原来做了 X，后来改成 Y"这类返工叙事（详见 `docs/项目整理.md` 第四节）
5. **分工边界**：只改自己任务对应的目录；要动别人的文件先在群里说明
6. **接口冻结纪律**：《引脚分配表》**9/23 已冻结**（计划 9/28）、驱动接口 **10/14 冻结**；车架与 PCB 的尺寸孔位由王政淋与李昕程**当面商定**；冻结后只加功能不改接口，变更需双方确认
7. **不猜规则**：判罚与评分相关问题，先读 `参考资料/原文件/` 原文，不凭印象下结论
8. **算法与调试不分离**：智能体可以写代码、分析遥测日志，但上车调参必须是人
9. **不要动“规范文件”**：`AGENTS.md`、`说明书.md`、`README.md`、`docs/`、`.gitignore`、`.gitattributes`、`.bat` 脚本由组长维护——组员身份下需要改就告诉用户，别自己动手；`项目记录/` 是共享区，鼓励更新
10. **不确定的事不要写死**：故障真因、物理/机械解释（打滑、丢脉冲、零偏…）、标定值、
    单次实测的结论，都要写成**推定/疑似/待验证** + 证据 + 备选解释；
    写法细则见 `docs/文档维护.md` §0（这条是为了防止下游 AI 把推测当事实继续传播）
11. **别把你的私有目录带进仓库**：reasonix / codebuddy / cursor / claude 等工具会生成 `.reasonix/`、`.codebuddy/` 之类的配置目录——常见工具已写进 `.gitignore`；若你用了其他工具产生新目录，请**先加进 `.gitignore` 再提交**，或告诉组长

## 五、多智能体协作（各人各带一个 agent 时）

| 原则 | 做法 |
|---|---|
| 唯一事实来源 | 任务分工与交接以 `项目记录/开发记录.md` §3 为准；agent 之间不靠口头传话，直接读写同一份文件 |
| 交接物 | 按 §3.2 交接时间线交付（如 P02 驱动接口文档 → A01/A02） |
| 冲突避免 | 文件边界（谁的文件谁动）+ 动手前先 `git pull` |
| 提交格式 | `类型: 内容`（一键脚本会自动拼类型）；对方 agent 靠类型前缀筛选历史 |
