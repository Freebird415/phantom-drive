# docs —— 项目规范（"必须怎么做"）

> 这里放**规矩**：技术红线、接口契约、文档维护、项目整理、智能体对接。
> 放事实与过程的不在这里：**做到哪了** → `项目记录/`；**谁什么时候交什么** → `计划和任务/`；**数据** → `logs/`。

## 这个目录有什么

| 文件 | 什么时候读 |
|---|---|
| `agent对接.md` | **AI 的总地图**：你是谁 → 该进哪个工作区 → 只能改哪些文件（含留言板规则）|
| `技术约定.md` | 写代码、画板、接线、定接口前的红线 |
| `遥测协议.md` | 写固件输出 / 写上位机解析前（帧格式、字段、`state` 码）|
| `引脚分配表.md` | 接线、改引脚前（**v3.0 已冻结**）|
| `文档维护.md` | 改完东西要同步 `项目记录/` 时（含**留言板规范**）|
| `项目整理.md` | 用户说"做一次项目整理 / 全面检查"时 |

## 给 AI 的入口

1. 先读仓库根 `AGENTS.md`（硬规则）→ 再读 `docs/agent对接.md`（地图）；
2. 动手前扫 `项目记录/决策登记.md`（已拍板/已冻结事项）；
3. 各工作区还有自己的入口：`firmware/agent对接.md`、`hardware/agent对接.md`。

> 本目录属于**规范文件**：组员/组员的 AI 不要自行修改，需要改就先说，由组长处理（见 `AGENTS.md` 硬规则 5）。
