# 遥测协议

> 固件 ⇄ 上位机（`tools/`）之间的数据约定。**改协议要两边同时改，且需双方确认。**
> 最后更新：**2026-10-10** · v1.8（v1.5 事件码以源码为准；v1.6 新增超声波“存在性保证”；v1.7 同步现装探头角度 35° → 15°；**v1.8 同步：OLED 放弃（器件数 8→7）、BLE 识别故障已闭环**）
> 帧格式**未变** —— 没有新增/删除/换序任何字段，旧解析脚本不受影响。

## 一、物理层

| 项 | 约定 |
|---|---|
| 接口 | USART1（PA9 = TX，PA10 = RX），接 USB-TTL |
| 参数 | 115200 8N1（数据量大了再升 460800；升之前两台机器都要改） |
| 速率 | `$T` 帧 100 Hz（板载）；**BLE 上：分频 2 ⇒ 50 fps**（2026-10-01 由 33→50，实测送达 44.8 fps）；`$U` 帧：主循环每 **100ms 一颗、左右轮流**（每颗 5 Hz、帧 4 Hz；**BLE 上 4 Hz 限流**，实测送达 3.3 Hz；`AUTO` 可关）；`$P` 上电一次；`$E` 事件触发 |
| 方向 | 车 → 电脑：`$T` / `$P` / `$E` / `$U`（后两者 2026-10-01 起也走 BLE，4Hz）；电脑 → 车：命令文本行 |

> **帧间隔约定（重要，改固件分频时必须知道）**：控制环固定 **100Hz** ⇒ **帧间隔 = 10ms × BLE 发送分频**。
> 工具不再写死这个值 ✗（本项目在“写死常量”上栽过多次），而是 `shared_log.frame_timing()` 从日志的
> `ms` 列推出来：分频 3 ⇒ ×3/30ms、分频 2 ⇒ ×2/20ms、板载快照 ⇒ ×1/10ms ✓
> （历史包袱：2026-10-01 之前的日志 `ms` 是“帧号×40”的合成值，`frame_timing()` 会特判 40ms ⇒ 仍按 ×3 处理 ✓）

## 二、帧格式

**通用规则**：ASCII、每帧一行、以 `\r\n` 结尾、逗号分隔、以 `$` + 类型字母开头。

### 2.1 `$T` 遥测帧（100 Hz）

```
$T,<ms>,<s0>,<s1>,<s2>,<s3>,<s4>,<s5>,<s6>,<s7>,<err>,<pwm_l>,<pwm_r>,<state>
```

| 字段 | 含义 | 类型/范围 |
|---|---|---|
| ms | 上电毫秒数 | 整数 |
| s0..s7 | 八路灰度二值化结果（**0=白，1=黑** —— 与模块原始极性相反，由 `app_trace.c` 归一化） | 0/1 |
| err | 循迹偏差（传感器编号单位，0 = 正中） | 一位小数，约 −8.0~+8.0 |
| pwm_l / pwm_r | 左右轮 PWM 占空比 | 整数，−100~100（负=反转） |
| state | 状态机 | 0=待机/丢线 1=循迹 2=避障 3=回线 4=精停 5=**起步找线** 6=**丢线找线**（5/6 均 2026-10-01 新增；2~3 为 A02 预留）|

> ⚠️ **`pwm_l/r` 是「算法打算给的值」，不等于电机实际得到的值。**
> 发车开关关着（`TRACE 0`）时电机不动，但 `$T` 照样报算法算出来的数 ——
> 这是**有意的**：可以上车前先在电脑上干看一遍算法输出对不对。

### 2.2 `$P` 参数帧（上电 1 次；`SET` 成功后也发一次）

```
$P,<ms>,<kp>,<ki>,<kd>,<base_speed>
```

> 作用：参数快照。**在线调参不会进 git**，靠这一帧把"当时用的是哪套参数"记进日志。

### 2.3 `$E` 事件帧（事件发生时）
```
$E,<ms>,<code>,<note>
```

**固件当前真正在发的码**（以源码为准：`grep -rn Tlm_SendEvent firmware/src/`）：

| code | note（固件原文） | 什么时候发 |
|---|---|---|
| **80** | `FINISH LINE` | 循迹：看到全黑 / 终点线 |
| **80** | `AVOID: left near` / `AVOID: right near` | 避障：某一侧进入门限 |
| **81** | `FINISH STOP` | 精停完成（正常流程 ✓）|
| **82** | `FINISH TIMEOUT` | 精停超时兜底（等不到条件就直接刹车 ✓）|
| **83** | `START T ignored` | 起步找线阶段看到 T 头但**不当终点**（闸①）|
| **84** | `FIN gated: too short` | 看到全黑但**里程不够**，不当终点（闸②）|
| **90** | `PONG` | `PING` 的应答 |
| **92** / **93** | `GRAY_ONLINE` / `GRAY_OFFLINE` | 灰度在线状态变化（离线时算法禁止驱动电机 ✓）|
| **94** | `MPU REINIT` | 陀螺仪自愈重初始化 |
| **95** / **96** / **97** | `SEEK ON\|OFF` / `ANALOG ON\|OFF` / `GYROD ON\|OFF` | 三个开关的确认 |
| **97** | `BOOT` | 上电 |
| **99** | `UNKNOWN_CMD` | 收到不认识的行 |

> ⚠️ **两处“同码不同事”**（看 `note` 区分，**别只看 code** ✗）：
> ① **80** —— `FINISH LINE`（循迹）与 `AVOID: …near`（避障）共用；
> ② **97** —— `BOOT` 与 `GYROD ON/OFF` 共用。

> **预留未用**：`1` 丢线 · `2` 检测到障碍 · `3` 开始绕行 · `4` 回到循迹线 · `5` 通过赛段标识 · `6` 到达终点
> —— 这些是留给 A02 状态机的编号，**当前固件不发** ✗；`91`（参数已修改）/ `98`（演示事件）旧文档列过，
> 源码里同样找不到发送点 ⇒ **勿依赖**（要用就由发送方自行补 `Tlm_SendEvent(code, note)` ✓）。

`note`：不含空格的短标签（便于人眼扫日志）。

### 2.4 `$U` 超声波帧（主循环每 100ms 一颗、左右轮流 ⇒ 每颗 5 Hz、帧约 10 Hz）

> ⭐ **2026-10-01 起：`$U` 与 `$E` 也走蓝牙了**（此前只走串口 ✗，导致“避障只能在插线时调”✗）
> - 频率：测量 **100ms 一颗**（每颗 5 Hz）；**BLE 上 4 Hz 限流**（250ms 一条，≈100 B/s）
> - 实测（2026-10-01，12~15 秒样本）：`$T` 送达 **43~45 fps**、`$U` 送达 **3.1~3.3 Hz** ✓
> - 形式：**纯文本行**，与串口完全一致 ⇒ 接收端靠 `AA 55 AA 55` 重新对齐（ASCII 不可能产生 0xAA，安全 ✓）
> - 固件：`app_log.c` 的 `Log_BleUsFrame()` / `Log_BleEvent()`；调用点：`main.c` 的自动测量块 + `Tlm_SendEvent()`
> - 工具：`btlog.DeFramer` 会先把文本行抽出来（`$T` 帧不受影响 ✓）；btview 有**超声波俯视图**
> - ⚠️ 负值语义：`-2` = 没回波（=前方空旷，**不是故障** ✓）；`-1` = 真故障（查线）；
>   **`-6`/`-3` = 驱动拦下重复触发（不是“没测到”）** ⇒ 显示端应保留上一个值，不要当成无数据
> - 命令 `US` 也会立即推一条到蓝牙 ✓

```
$U,<ms>,<l_mm>,<r_mm>
```

| 字段 | 含义 | 类型/范围 |
|---|---|---|
| ms | 上电毫秒数 | 整数 |
| l_mm / r_mm | 左（PA4/PA5）/ 右（PA1/PB5）距离 | 整数，单位 mm；**−1 = 无回波（真故障），−2 = 前方空旷/超量程** |

> 为什么要这个帧：超声波是避障的唯一输入，测量值必须能和其它量一起落盘/画图。
> 节拍由驱动层保障：**两颗不能同时触发**（轮流）+ 同一颗两次间隔 ≥60ms + 失败后 600ms 恢复期。
> **实测**：250ms 一颗（左右各 2Hz）成功率 100%；曾试 100ms 一颗，左侧掉到 42% —— 所以默认是 250ms。
> **兼容性**：这是**新增帧类型**，没有改动 `$T/$P/$E` 的任何字段（符合 §四 扩展规则）。


## 三、命令（电脑 → 车）

每行一条，`\r\n` 结尾：

| 命令 | 作用 | 回复 |
|---|---|---|
| `PING` | 连通性测试 | `$E,<ms>,90,PONG` |
| `GET` | 读当前参数 | `$P` 帧 |
| `SET <名字> <值>` | 改参数（如 `SET kp 1.35`） | `$P` 帧（改后的值） |
| `US` | 立即测一轮超声波（左→隔 60ms→右） | `$U` 帧 |
| `TRACE 0\|1` | **循迹算法发车开关**（0 = 只算不发，1 = 真的驱动电机）| `# TRACE drive=N` |
| `AVOID 0\|1` | **避障算法发车开关**（同上）| `# AVOID drive=N` |

可调参数名：`kp` `ki` `kd` `base_speed`。

> **完整命令表**（含各驱动的 bring-up 自检命令，共 20+ 条）见 `firmware/驱动接口说明.md` §六；
> 本节只列**与本协议帧直接相关**的命令。
>
> ⚠️ **算法发车开关出厂默认 0（只算不发）** —— 这是安全设计：烧录后车不会自己窜出去。
> 要真发车必须显式发 `TRACE 1`，且**开之前先把轮子架空**。

## 六、拿到这份协议后怎么干活（A01 熊雅琦 / A02 毕烨恺）

### 6.1 一分钟跑通一次记录（不用插线）

1. 车通电（BLE 上电默认开 ✓）；双击仓库根目录「**蓝牙日志.bat**」→ 自动开浏览器界面
2. 等左上角显示 **● 蓝牙已连接**（自动连，连不上每 5 秒重试 ✓）
3. 点「**开始接收**」→ 跑你的车 → **关键处按空格**（打点）→ 点「**停止接收**」
4. 想留某一段：点「**导出片段…**」填帧号范围（打点可一键当起/止）+ 起个名 ⇒ 独立目录（含 `note.md` 汇总 ✓）
5. **只想看、不想存文件**：点「**监测**」（不写任何文件 ✓；监测中按空格 = 一键开始/停止记录，
   并把**最近 ~65 秒**的数据一起存进 CSV ✓ —— 现象出现了才按也来得及）

命令行等价物：`python tools/btlog.py --note "A4 直线" --seconds 30`（车通电即自动回传 ✓）

### 6.2 三条读法约定（都是踩过的坑，务必先看）

| 坑 | 事实 | 该怎么做 |
|---|---|---|
| **帧间隔** | 控制环固定 100Hz ⇒ **BLE 分频 2 = 每帧 20ms**（分频 3 ⇒ 30ms；板载快照 ×1 = 10ms）| **别写死 20ms** ✗；`shared_log.frame_timing()` 会从日志自己推；`derived.csv` 已算好 |
| **两把时间尺** | `$T` 的 `ms` 与 `$U`/`$E` 的 `ms` **不是同一个计数器**（`$T` 侧会 ~65.5s 回绕）| **跨类型不要用 ms 相减** ✗；同一类型内用 ✓（工具已处理）|
| **增量语义** | `dl`/`dr` 是**每 10ms 的增量**；BLE 每帧代表 `10ms × 分频` | 算速度：`(dl+dr)/2 × mm_每计数 × 分频 ÷ DT`（`note.md`/`derived.csv` 已算好）|

### 6.5 现在不能做的（免得白折腾）

- **命令下行只走串口**：本日志链是**单向**的（车 → 电脑 ✓），BLE 下行**未验收** ⇒ 改参数 / `TRACE`/
  `AVOID`/`SNAP` 等命令请用 **USB-TTL 接 USART1（PA9=TX / PA10=RX，115200 8N1）** ✓
- **不保证零丢帧**：无线实测送达约 **45 fps / 50 fps（约 90%）**；要看**每一次 10ms 采样**（例如精停那一下）
  就用**板载快照**（100 Hz 全精度、停车写 Flash、掉电不丢）：**长按 PA12 发车** → 跑完停车自动写 →
  `python tools/snapshot.py` 读出（`DUMP` 行格式与 `$T` 完全相同，可直接画图 ✓）

### 6.6 日志放哪 / 怎么给别人看

- 本机完整数据：`logs/<日期>_<时刻>[_monitor]/telemetry.csv`（**只读，不入库** ✓）
- 要给别人或 AI 看：录完/导出时会**自动**生成 `logs/共享_*.md`（3~6KB：汇总 + ASCII 曲线 + 关键帧）
  ⇒ **提交后别人就能看** ✓
- ⚠️ **任何脚本/智能体都不许往 `logs/` 写文件**（包括 `printf … > logs/…` 重定向 ✗）——
  那里是**唯一一份**真实跑车数据、不入库就等于没有备份 ✓
- 导出的片段是**嵌套**的（母日志 → `片段_xxx/` → 可在片段上再截）✓；删母日志时片段会被自动抬到上一层 ✓
