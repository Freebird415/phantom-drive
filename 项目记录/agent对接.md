> 两类读者：
> 1. **组员**：你打算用 pi / reasonix / Claude Code / Cursor 等智能体帮你干活 → 看第一节
> 2. **智能体本身**：你被拉进这个项目 → 从第二节的"必读顺序"和"行为规范"看起
>
> 最后更新：2026-09-12

## 一、给组员：让智能体三分钟进入状态

### 1.1 三步开场

1. 在**仓库根目录**打开智能体（它会自动读 `AGENTS.md`——那是项目的导航 + 硬规则）
2. 第一句话建议这么说：
   > 读一下 `AGENTS.md` 导航里的文件，告诉我：我负责哪些任务、现在该做什么。
3. 之后每次开新任务，先说清三件事：**我是谁（任务号）**、**要做什么**、**做完给谁**

### 1.2 提示词模板（可直接抄）

| 场景 | 建议说法 |
|---|---|
| 找任务 | 我负责任务 H02，读 `项目记录/开发记录.md` 的 3.1、3.2、3.3，告诉我交付物、DDL 和上下游 |
| 技术活 | 按 `docs/技术约定.md` 检查我这份接线/代码方案有没有违反红线 |
| 排障 | 读 `项目记录/经验与踩坑.md`，看有没有和这个现象相关的坑 |
| 写文档 | 我做了 XXX，按 `docs/文档维护.md` 的规则更新项目记录 |

### 1.3 三条纪律（用智能体的组员请记住）

1. **智能体不能替代实测**：调参、装车、跑赛道必须人来做（分工里写明的"含实测调参"就是指这个）
2. **提交前你自己过一眼**：用一键脚本提交；agent 改了什么、提交信息是什么，由你负责
3. **别把不该给的东西喂给外部服务**：发票、个人信息、账号密码不要粘给 AI
4. **agent 越界要拦下**：如果 agent 改了 `AGENTS.md`、`说明书.md`、`README.md`、`docs/` 或两个 `.bat`，**先别提交**，在群里说一声——这些是组长维护的“规范文件”；`项目记录/` 才是大家都能改的共享区

## 二、给智能体：进入项目后的必读顺序

| 顺序 | 文件 | 什么时候读 |
|---|---|---|
| 1 | `AGENTS.md` | 永远先读（导航 + 硬规则） |
| 2 | 本文件 | 永远第二个读（背景速览 + 行为规范） |
| 3 | `docs/技术约定.md` | 写代码、画板、接线、定接口前 |
| 4 | `项目记录/开发记录.md` | 需要方案、13 项任务、交付物、进度、物料时 |
| 5 | `项目记录/经验与踩坑.md` | 排障、做技术决策前 |
| 6 | `参考资料/原文件/` | 涉及比赛判罚与评分判断时（以原文为准） |
| 7 | `报销/README.md` | 处理发票、报销、成本相关事务时 |

## 三、项目速览（30 秒版）

- 题目：工创课「重走古丝路 · 自动循迹避障小车」（华南理工大学 工程训练分散项目）
- 任务：全自动循迹（4 赛段）+ 动态避障（4 个随机摆位障碍物）+ 终点精停
- 平台：STM32F103C8T6 · 亚博智能八路灰度 · TB6612 · 三轮构型
- 时间：第 4 周启动，预测第 9 周比赛；内部冻结死线第 8 周末
- 团队：5 人、13 项任务（见 `项目记录/开发记录.md` §3）
- 仓库：GitHub 私有仓库 `phantom-drive`

## 四、智能体行为规范（本项目特有）

1. **提交必须经用户确认**：不要自作主张 `commit` / `push`；改完停下汇报，等用户说"提交"
2. **文档同步**：完成活后按 `docs/文档维护.md` 更新 `项目记录/开发记录.md`（正向）与 `项目记录/经验与踩坑.md`（踩坑/试错）
3. **降噪**：正向文档只写"现在应该怎么做"，不写"原来做了 X，后来改成 Y"这类返工叙事（详见 `docs/项目整理.md` 第四节）
4. **分工边界**：只改自己任务对应的目录；要动别人的文件先在群里说明
5. **接口冻结纪律**：《引脚分配表》《安装接口契约》第 3 周末冻结，驱动接口第 5 周末冻结；冻结后只加功能不改接口，变更需双方确认
6. **不猜规则**：判罚与评分相关问题，先读 `参考资料/原文件/` 原文，不凭印象下结论
7. **算法与调试不分离**：智能体可以写代码、分析遥测日志，但上车调参必须是人
8. **不要动“规范文件”**：`AGENTS.md`、`说明书.md`、`README.md`、`docs/`、`.gitignore`、`.gitattributes`、两个 `.bat` 由组长维护——需要改就告诉用户，别自己动手；`项目记录/` 是共享区，鼓励更新
9. **别把你的私有目录带进仓库**：reasonix / codebuddy / cursor / claude 等工具会生成 `.reasonix/`、`.codebuddy/` 之类的配置目录——常见工具已写进 `.gitignore`；若你用了其他工具产生新目录，请**先加进 `.gitignore` 再提交**，或告诉组长

## 五、多智能体协作（各人各带一个 agent 时）

| 原则 | 做法 |
|---|---|
| 唯一事实来源 | 任务分工与交接以 `项目记录/开发记录.md` §3 为准；agent 之间不靠口头传话，直接读写同一份文件 |
| 交接物 | 按 §3.2 交接时间线交付（如 C1 接口文档 → C2/C3） |
| 冲突避免 | 文件边界（谁的文件谁动）+ 动手前先 `git pull` |
| 提交格式 | `类型: 内容`（一键脚本会自动拼类型）；对方 agent 靠类型前缀筛选历史 |
