## 3. 每次"两个智能体之间的分歧"都要回到这张表

碰到分歧时按此顺序判：

1. 本表里有 **已冻结** 结论 → 以本表为准，**不接受重新推导**；
2. 本表里有 **生效中** 结论 → 以此为默认，要改走 §4；
3. 本表里是 **待定** → 谁负责谁定，定完**先登记再动手**；
4. 表里没有 → 查 `docs/引脚分配表.md` / `hardware/电气设计/电气连接规范.md`；
5. 都没有 → **停下来问组长**，不要自己拍。

---

## 4. 变更流程

1. 发现要改 → **先在群里说**（涉及引脚/总线/串口必须双方确认）；
2. 在本表里把该条状态改为"变更中"，写清原因；
3. 改源头数据（`硬件：hardware/电气设计/生成接线图.py` 或对应规范；
   固件：`firmware/`；文档：`项目记录/`），**不要只改产物**；
4. 重跑 `python hardware/电气设计/生成接线图.py --build` 与 `python hardware/电气设计/自检.py`（退出码必须 0）；
5. 同步下游引用（`docs/引脚分配表.md`、`firmware/README.md`、`开发记录.md` 等）；
6. 本表登记新结论 + 日期；
7. `commit`/`push` **必须经用户确认**。
