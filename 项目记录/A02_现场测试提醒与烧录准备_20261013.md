## 4. 第一次上电，只做静态观察

你只需把小车留在架空台面，打开现有串口接收或「蓝牙日志.bat」接收日志，不按发车键。

- 观察轮子持续静止、心跳/供电状态正常，无冒烟、异味、异常发热或线缆拉扯；异常立即断电。
- 核对真实新帧持续到达，不能只看界面“蓝牙已连接”。串口已在用就读串口，不额外要求接新TTL线。
- 若捕获到启动事件，应看到 `AVOID build a02-s1-count-trial` 和 `A02 TEST en0 dir1 trigger2000 counts`。主程序仍有旧的`BOOT a02-v1-20261010-20cm-trial`文字，它不是当前A02版本依据。以已验证bin/hash及新的A02标识为准。
- BLE连接较晚可能错过一次性启动事件，此时不以缺少版本事件判刷错；保留烧录校验记录，核对持续健康日志。
- 静置至少2秒，观察 `AV G v1 s0 b1`，a≤80ms；v=有效、s=驱动状态、b=标偏就绪、a=缓存年龄、r=原始陀螺LSB、f=失败数。静止时r/gz接近0可以正常，不能据此判坏。
- 用已有黑线样片确认灰度在线/黑白合理，不移动或拆装正在旋转的机械件。`GRAY_OFFLINE`出现时不能把模拟灰度当实测值。
- 待机的遥测可能报算法“只算不发”的PWM/state，**日志数字非零不等于电机已使能**。以驱动关闭状态、实际轮子静止和已核对的启动代码为准。
- 健康未就绪、读取失败、重启循环或轮子未经操作自行转动时，结束本轮并分析，不进入运动测试。

完成静态检查后才由人决定开始哪一侧的架空运动测试；不把“刷完”当作发车许可。

| 1. 在哪个state/阶段失败？ | 最后正常state、内部p、E88原文及前后帧；区分“主动脱线”“搜线失败”“反馈故障”“恢复后A01丢线” |

| 4. 何时重新看到线？ | 第一次1～4路连续黑、p6进入、后续是否又丢失及最终E4。搜线时间用同一E时钟从p12到首次p6；稳定回线时间另报到E4 |

必须记录的字段：日志目录、固件hash/en/dir、参数组、试次/方向、现场视频/现象；T帧时间、s0～s7、err、PWM L/R、state、dl/dr、gz；U帧左右mm；E事件编号、文本、p/c/dir、健康字段。CSV gz已是°/s，不再乘2；AV G的r为原始LSB。

**回线距离**先报告“p12至首次p6的计数差”和“p12至稳定交接的计数差（有足够证据才报）”。没有末端计数事件/连续可靠数据就写缺测。若附毫米，只能写按0.115mm/计数得到的**名义行程、未精标**；不能当准确横向位移或真实回线距离。可在停车后另行实测，但不能倒推编造。

T与E/U的设备时间尺不同，不直接相减；跨类型按接收顺序/接收时间对齐。事件缺失、帧率过低或版本不明时给出不确定性，不计入可靠验收。

快照容量1200帧约12秒，写满停止记录且不会自动清上次数据；BLE持续接收为主。先备份历史数据，再讨论是否清快照，本流程不自动清理。

### 单变量调参

顺序：**OUT脱线计数 → FWD前进计数 → RETURN反摆计数 → 目标速度 → PWM舵量**。一次只改一项，记录“旧值／新值／原因／预期／结果／保留或回退”。幅度先≤10%，改后重编核验体积并记录新hash；不在场地一边跑一边改。

保持30mm、反馈有效性/一致性、350ms居中、PWM和时间/里程上限。未先查明故障原因，不调大保护边界来掩盖失败。不改A01 PID，不加入真实障碍或动态路径规划。
