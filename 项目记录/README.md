# 项目记录 —— 事情"发生了什么 / 决定了什么"（共享区）

> 这里**任何人都可以更新**（与 `docs/` 的规范文件不同）。
> 但它们有严格分工，别互相串味——**写之前先看 `docs/文档维护.md`**。

## 七份文件（前四份是核心台账，后三份是索引 / 操作卡 / 单项建议）

| 文件 | 定位 | 一句话判据 |
|---|---|---|
| `开发记录.md` | 正向流程（纯净） | 只写"**现在该怎么做**"：方案、分工、接口、物料、进度、里程碑 |
| `实际进度.md` | 完成台账（事实层） | 只写"**已经发生了什么**"：谁、哪天、交了什么、卡在哪；不抄计划 |
| `经验与踩坑.md` | 全量记录（不降噪） | 踩坑、试错、被否决的方向、背景信息、风险、待确认项 |
| `决策登记.md` | 已拍板 / 已冻结台账 | **动手前先扫**；两个 AI/组员有分歧时先查它（§3 裁决顺序）|
| `版本索引.md` | 固件版本索引 | A01 基线与各版本的 Git 定位、源码哈希、回滚入口 |
| `比赛日操作卡.md` | 上场前必读 | 发车 / 终点 / 合规红线（依规则原文整理）|
| `A02避障算法迭代建议.md` | 单项方案建议 | A02 避障的四步迭代路线与验收门槛（**10/14~10/18 按日推进，两个关卡 10/16 / 10/17**）|

## 常见写错的地方

- ❌ 把"试错过程"写进 `开发记录.md`（那是 `经验与踩坑.md` 的活）；
- ❌ 把"计划"抄进 `实际进度.md`（计划归 `开发记录.md`，两处对不上最麻烦）；
- ❌ 把没复现的推断写成事实（见 `docs/文档维护.md` §0 铁律）；
- ❌ 改完不更新文件头的"最后更新：日期 · 版本"。

> 进度类的一句话交接也可以走 `留言板.md`（仓库根 / 各工作区），但**流水账不进留言板**。
