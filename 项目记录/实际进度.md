## 二、事件记录（倒序，均可由提交历史核对）

### 2026-09-23（面包板 bring-up：OLED）
- **0.96" SSD1306 OLED 调通并验收**（I2C2：PB10/PB11，上拉 3.3V）：0x3C 应答、初始化序列下发、
  **128×64 全屏棋盘格 + 四周边框正确显示**（照片存 `参考资料/原文件/oled测试显示/`）
- 型号/地址/上拉由**背面丝印照片**确认（`0.96 OLED` + `IIC ADRESS SELECT 0x78` + `472`=4.7k 板载上拉）
- 固件新增 `drv/drv_oled.{c,h}` 与命令 `OLSCAN`（只探地址）/`OLED`（初始化+画测试图案）；
  `HAL_I2C_MspInit` 归位到 `bsp`（HAL 只允许一个定义，统一管 I2C1+I2C2）
- 关键约束：**OLED VCC 必须 3.3V**（板载上拉拉到 VCC，接 5V 会把 I2C2 拉高，将来会打坏 MPU6050）

### 2026-09-23（面包板 bring-up：灰度）
- **感为八路灰度 I²C 调通并验收**：扫到 7bit **0x4C**、ping 回 0x66；扫白面包板时 **8 路模拟量摆幅 18~134**（按 6→5→3→7→1 依次起伏）；
  **校准后 `dir` 正确分档**（5/6/7 路判黑，且正好是模拟量最高的三路）→ 数字判定与模拟量交叉验证一致
- 固件新增 `drv/drv_grayscale.{c,h}`（硬件 I2C1 重映射 PB8/PB9，100kHz）与 bring-up 命令 `GR`、`GRSCAN`（总线扇描，排错神器）
- 新增判定：**`ana` 全 0 + `dir` 全 0 = 没照到面**（不是坏了）；**上拉必须 5V**（手册 72% 规则，面包板上插模块板载 PULL 跳帽）

### 2026-09-23（面包板 bring-up：超声波）
- **超声波 ×2 调通并验收**（李沛阳 + 王政淋接的线）：固件新增 `$U` 帧（10Hz→实际 4Hz）与 bring-up 命令 `US` / `AUTO`；**右侧三轮 100%、左侧打正时 100%**，两颗中位读数一致（322/332mm）
- **修掉 3 个真 bug**：①命令在串口中断里执行→输出被静默丢掉；②主循环与命令两个触发源撞节拍→假“超量程”；③失败后密集重触发→模块锁死（加 600ms 恢复间隔）
- **实测出两条安装约束**：探头**距反射面 ≥ 25~30cm**（< 20cm 掉到 37~58%）；探头必须**平行正对**（波束角仅 ~15°）
- **firmware 目录重构**（按用户要求建立可读性规则）：`src/bsp|drv|app` 三层 + `README.md` 新增《目录规则》（依赖方向只允许 app→drv→bsp；新增器件 = drv/一对文件 + 注册自检命令；src/ 只放会编进固件的源码）
