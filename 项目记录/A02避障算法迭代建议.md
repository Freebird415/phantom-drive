## 0. 一句话结论

**现在的避障不是“调得不够好”，而是“架构太脆”：**
它把陀螺积分出来的航向当成整套几何的地基，地基一抖（`gz` 恒 0），规划、外廓保护、回线全部失效。

**要改的不是参数，是架构：**
> 触发时**算一次**，然后**开环执行到底**，退出只认一件事——**灰度看到线**。
> 绕障全程真正必须实时盯着的只有三样：**线、障碍、走了多远**。

## 1. 先看清痛点（为什么迭代算法没有效果）

### 1.1 三个叠加的问题

| # | 问题 | 直白解释 |
|---|---|---|
| ① | **耦合的状态估计** | 陀螺 → 航向 `yaw` → 位置 `(x,y)` → 曲率模型 → 外廓预测。这条链上**每一环都是必需输入**，任何一个失真，整条几何都错 |
| ② | **没有降级路径** | 模型说“过不去”就直接 `AVOID footprint guard` 刹车停车，而不是“退化成简单策略继续跑” |
| ③ | **地基是名义值** | `mm/计数 0.115`（三组数据还互相矛盾）、轮距 150、车宽 195.5、探头偏移 40（标注“待量”）、障碍 181（圆整）……**精度并不存在，复杂度却已经上来了** |

### 1.2 结果就是“迭代没有效果”

改一个参数，误差就转移到另一个环节（已经发生过：曲率 EMA 残留导致一接管就外移错；回线模型不对导致 `line not found`）。
**这不是调参问题，是“用模型去凑现象”的必然结果。**

### 1.3 一个必须记住的事实

现在的 A02 在接管期间是**独占**的：`main.c` 里 `if (Avoid_Mode()) { Avoid_Step(); } else { Trace_Step(); Avoid_Step(); }`
—— **绕障全程 A01 完全暂停**，灰度、电机、`$T` 都由 A02 自己管。
所以 A02 一旦 `FAULT` 刹车，**A01 不会自己接回去**。

## 2. 陀螺怎么用：从“控制必需品”降级为“诊断仪器”

**结论：陀螺不进最终避障计算，只用于日志分析。**

- 目前它在 A02 里参与 8 处：零偏、偏航率、航向积分、航位推算、航向控制阻尼、跟线阻尼+交还闸门、赛道曲率模型、外廓保护。
  **注意：陀螺只提供 1 个量（偏航率），是“积分成航向”之后被 5~6 处消费** —— 所以它一死不是“少一个传感器”，是**整个坐标系坏了**。
- 它适合干的活（本来就是它的定位，`决策 E-24`）：**事后分析姿态**——比如“这次过度差速，是不是直接把车转出跑道了”。
- **前提**：日志里的 `gz` 必须能区分“真的没转”和“传感器死了”。现在 `app_log` 是“每 4 拍刷一次 ≈25Hz + 读失败保留旧值 + 无有效性标记” ⇒ **分析也会被骗**（已经吃过一次亏）。
  → 建议：加一个 `gz_valid` 位或“失效事件”打点，至少让日志自己说清楚。
- 如果以后真的需要姿态：用**编码器差速**（`Δθ = (Δs_R − Δs_L) / 轮距`）+ 灰度线做绝对修正；仓库里 `tools/track.py` 就是**纯 `dl/dr`** 的航位推算，数学可以直接借用。

## 3. 四步迭代（每步都有验收，没验收不算“跑通”）

> 总原则：**每加一步，只引入一个新变量。** 上一级的可复现性没拿到，不要进下一级。

### 第 1 步 · 无障碍：先验证“脱离 → 回归”本身

- **做什么**：写一段“主动向左/向右脱离跑道 → 走一段大致曲线 → 回到跑道”的动作，只管脱离和回归，**不管障碍、不用超声**。
- **怎么触发（很重要）**：比赛**不能遥控**（规则禁止 + BLE 下行本来也不通）⇒ 触发必须**车载**：例如“起步后走 N mm”或“发车后 T 秒”，方便反复复现。
- **扫 2~3 个速度**：最小转弯半径随速度变，低速测得好看没有意义。
- **本步要产出的实测数**（后面全靠它）：
  1. 该速度下的**最小转弯半径 `R_min`**；
  2. 完成一次“外移”需要的**里程 / 时间**；
  3. 回到线后的**对线误差**（`|err|`）。
- **验收**：**10/10 成功**；回归后 1 秒内 `|err| ≤ 1`；**全程不反转**。

### 第 2 步 · 放障碍：固定参数 → 固定轨迹

- **做什么**：超声只当**触发器**（哪一侧、多远），然后执行**同一条固定轨迹**（就是第 1 步那段动作，只换目标侧和横向量）。
- **测什么（摆位 × 速度矩阵）**：

  | 摆位 | 为什么这么摆 |
  |---|---|
  | **贴线边**（最刁） | 障碍“位于循迹线任意一侧”，贴着线边的 60×60 障碍会落进**车体走廊** |
  | **紧贴线边（半压线）** | 最容易被判成“线不居中”的干扰 |
  | **离中线较远** | 对照，验证不会误触发 |

  × 左右两侧 × 2 个速度，**每格至少 5/5**。
- **每格记录**：实际触发距离、实际横向让开量（从编码器算）、完成里程、是否零接触（人眼/视频确认）。
- **验收**：所有格子 **5/5、零接触**；触发距离/让开量记录成表。
- **关键工程要求**：这段机动代码**只写一个函数**，参数是 `(side, Δ, L_shift, L_pass, v)`。
  这样第 2 步测出来的数据，**直接就是第 3 步公式的依据**。

### 第 3 步 · 瞬时计算：算一次、执行到底（详见 §4）

- 把第 2 步里“写死的横向量/里程”换成**由 `侧 + 距离 + 车速` 算出来的值**；
- 依然是**算一次**，执行到“灰度看到线”为止；
- **验收**：成功率不低于第 2 步，且能覆盖第 2 步**没测过**的“距离 × 速度”组合；仍然零接触。

### 第 4 步（可选）· 复杂实时避障

- 连续重规划、多障碍博弈之类。
- **建议：除非第 3 步已达标且时间富余，否则不做。**
- 理由：比赛的 4 个障碍**分在不同赛段、每段只来一个**，连续重规划收益极低、风险很高。

## 4. 第 3 步的计算方案建议（算一次，执行到底）

> 目标不是“最精确”，而是“**一定不撞、一定能回来**”。

### 4.1 输入（触发那一刻取一次）

- `side`：哪颗探头先确认（左 / 右）；
- `d`：确认到的距离（mm）；
- `v`：当前车速（mm/s，编码器算）。

### 4.2 参数（**全部用第 1/2 步的实测值**，不要拍脑袋）

| 参数 | 含义 | 取值建议 |
|---|---|---|
| `Δ` | 横向让开量 | 车半宽 + 间隙（2~3cm）+ 跟踪余量 ≈ **140mm**；用第 2 步“成功过的量”替换 |
| `L_shift` | 外移段里程 | 第 1/2 步实测值（理论下限 ≈ `2·√(R_min·Δ)`，仅作参考） |
| `L_pass` | 通过段里程 | **180mm + 余量**（规则里最大底面 150×100 的对角线；与实测无关，保守即可） |
| `L_in` | 回归段里程 | `= L_shift`（**对称回来**，不依赖任何赛道模型） |

### 4.3 执行（三段，全开环）

1. **外移**：用第 1 步那条曲线，朝 `side` 平滑外移到 `Δ`；
2. **通过**：保持 `Δ`，直行 `L_pass`；
3. **回归**：**对称**往线方向回移；**一旦灰度看到 1~4 路连续黑（真线）就立刻结束机动**，转入“跟线回正”，再交还 A01。

### 4.4 触发门限

`d_trigger = a + b · v`（`a`、`b` 用第 2 步数据拟合）。
**原则：误触发代价 ≪ 漏触发代价** —— 撞上 = 该障碍 0 分，多绕一次只是慢一点。

### 4.5 明确“不做”的事（这是“降维”的核心）

- ❌ 航向 `yaw` 积分、位置 `(x,y)` 航位推算；
- ❌ 赛道曲率模型（`av_line_y(x)=0.5·curve·x²`）；
- ❌ 外廓 SAT 预测保护（`AVOID footprint guard` 那套）；
- ❌ 绕障过程中再用超声重新判定/重新规划。

**只保留两件与超声有关的事：① 触发时取一次“侧+距”；② 全程 `≤30cm` 急停。**

### 4.6 兜底（有界、**永不反转**）

回归段走完仍没看到线 → 朝“最后看到的线那一侧”做**有界小幅扫线**（≤ ~150mm）→ 仍没有 → **减速直行找线** → 最后才停车。
⚠️ 规则原文：**“一旦逆行，本轮比赛结束”** ⇒ 全程绝不倒车。

### 4.7 边界情况

| 情况 | 处理 |
|---|---|
| 两颗探头同时报 | 取**更近/更早确认**的一侧 |
| 两侧都 ≤ 急停阈值 | 立即停（安全第一） |
| 计划横向量超出可用走廊（线靠跑道边） | 先“减速 + 尽量贴另一侧”；实在不行才停（停住只丢该段，撞上直接 0 分） |
| 绕障中灰度意外又看到线 | **立即结束机动**、转入跟线（别硬走完轨迹） |

## 5. 对现有代码：保留什么、删/降级什么

### 5.1 保留（便宜且值钱）

- ✅ **`≤30cm` 急停**（纯超声，不依赖姿态）；
- ✅ **超时 / 无进展保护**（“走不动就报故障”，比默默卡死强）；
- ✅ **`state=2/3`** 的日志标识（事后分析全靠它）；
- ✅ **不反转、不单侧盲开**（规则里脱线要扣赛段分）；
- ✅ **回到线后交还 A01**；顺带一提：A01 那边 `dt>50ms 就丢弃 D 项`的保护已经存在，所以暂停后交还**不会因 D 项爆表而猛打舵**。

### 5.2 删 / 降级

- ❌ `yaw` 积分与位置航位推算（`av_motion` 里的那部分）；
- ❌ 局部曲率与 `av_line_y`；
- ❌ 外廓 SAT 预测（或至少降级为“只打诊断点，不参与决策”）；
- ⚠️ 触发/绕行中的超声二次判定（只在触发时取一次 + 全程急停）；
- ⚠️ 每次触发的状态重置逻辑（越简单越好，别再有“曲率 EMA 残留”这类隐藏状态）。

## 6. 实战约束（写进流程，别忘）

1. **赛道上不能遥控**：所有测试触发都要**车载**（里程 / 时间 / 超声）——BLE 下行本来也不通。
2. **必须先把三个数标定掉**：
   - **轮距**；
   - **mm/计数**（用“绝对计数锚帧”，P01 阶段 3 的活）；
   - **15° 安装后的实际首次检出距离**（现在还是“名义几何”）。
   不标定，任何“绝对几何”的方案都只是名义值。
3. **每步都要可量化验收**（10/10、5/5、零接触、`|err|≤1`），否则“跑通了”是主观判断。
4. **速度要覆盖实际使用区间**（A01 现在的基准/上限是 22% 档）。

## 7. 附：规则摘录（判决依据，别凭印象）

- 障碍物 **4 个**，位于循迹线**任意一侧**，位置每轮**随机**摆放；
- 尺寸：**150×100×150** / **60×60×150** / **120×70×150** / **110×100×170**（mm）；
- **小车任何部件不得与障碍物发生任何接触**；撞开/撞移 = **避障失败**；障碍从车底穿过也不算成功；
- 每成功躲避一个 **+10 分**，避障总分 **40 分**；
- **逆行 ⇒ 本轮比赛结束**；非避障脱线 ⇒ 脱离期间所经赛段不计分。
