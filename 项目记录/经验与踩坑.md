## 3. 已澄清的重要事实（防止重复走弯路）

1. **"视觉模块"不存在**：王政淋名下所谓视觉模块，实为另一套八路红外/灰度传感器 → 本项目无摄像头方案，避障只能靠超声波 / ToF / 红外等
2. **旧车是"双轮自平衡 + 循迹"小车**：只能参考结构与拆件用料，不能直接改造成比赛车；且规则要求车架自制（一票否决）
3. **车架自制的边界**：允许螺丝、轴承等标准件，但**主结构**必须队伍自行设计 + 用中心设备加工，答辩要提供 CAD 源文件与加工照片/视频；"完全买现成"直接 0 分且不予参赛
4. **停止分是"精停"**：过终点线后车**尾**投影不得越过终点线
5. **时间分是相对值**：40 × t₁/t₂（对自己以外全场最快队）→ 时间快慢直接影响分数，不是"不被取消资格"那么简单
6. **非避障脱线要扣分**：脱线期间经过的赛段不计分 → 绕障必须"短、快、可控"
7. **电机很强**：JGB37-520 12V 333RPM + 大轮 ≈ 1 m/s 以上空载 → 算法必须限速起步，否则第一圈就跑飞
8. **车小有利避障**（规则原话）且尺寸上限 250×200×200mm 是每轮 −10% 的红线
9. **个人账号私有仓库的协作者只有"读写"一档**（GitHub 官方文档原文）：界面没有角色下拉框，也无法设只读/管理员；要细分权限只能把仓库转到组织（Organization）下——本项目不需要折腾
10. **电机是带编码器版本**（第 3 周确认）：JGB37-520 为 6 线（电机± + 编码器 VCC/GND/A/B）；BOM 已备编码器 6p 接口，引脚表已预留两路定时器编码器模式（TIM2/TIM4）。**不同批次线色可能不同，接线前必须实测复核**
11. **Blue Pill 板载 8MHz 晶振占用 PD0/PD1**：虽然固件用 HSI 8MHz→PLL→64MHz 不依赖它，但板上晶振仍物理连接 → **PD0/PD1 不可当 GPIO**；引脚预算按 35 个可用 IO 算（PA0~15 + PB0~15 + PC13~15）
12. **本项目的核心板还焊了一颗 32.768kHz 晶振**（实物照片：晶振旁黑方块丝印 `32768`）→ **PC14/PC15 也不可用**，可用 IO 降到 **33 个**（PA0~15 + PB0~15 + PC13）
13. **核心板的 4pin SWD 排针不含 NRST**（只有 3V3/SWDIO/SWCLK/GND）→ 必须自己再做一个含 NRST 的 5pin 排针，否则关了 JTAG 后跑飞就没法“连接下复位”就回
14. **实物亚博灰度是 YB-MUX04-2.0**，针序 `5V GND KEY RESET X1..X8 TX RX SCL SDA`；它**没有**老教程里的 AD0/AD1/AD2 + OUT 多路复用线（那是旧型号）→ 引用亚博资料时要注意新旧不一致，以**实物丝印为准**

## 4. 踩坑清单 / 避坑指南

### 电气
- 杜邦线靠摩擦接触，振动（车轮/电机/急转）下会间歇性松动——**间歇性故障是最难查的一类 bug**；成品禁用，连接规范见《开发记录》
- 电机动力线不能用细杜邦（24–26AWG 单针 ≤1A），JGB37-520 堵转可达 2A+
- **单电源**是规则硬要求（两块电池 −10%/轮）→ 12V 主电池 + 降压是唯一正解
- 电池必须加总开关与保险丝（规则也明确建议，防调试短路）
- 光电门相关：**车上的红外补光灯若水平朝前，可能提前触发对射光电门**（影响计时）→ 补光朝下并加遮光罩
- 国内打板/快递可能被国庆拖慢 → **PCB 9/30 前下单**（节前最后窗口）、**10/11 前点亮**

### 传感器与环境
- 红外/灰度怕环境光：广告布反光、现场灯光变化 → 加遮光罩 + 现场标定；这也是"传感器选型要抗光"的由来
- **光电门三种干扰**：①超声波可能把门柱当障碍物（起终点附近应设"禁避障区"）②车灯可能误触发计时 ③门附近光照/读数可能跳变（需现场实测 10 分钟验证）
- **回环赛道**：起始段有大回环，双线可能同时进入八路传感器视野 → 需要专门策略（如靠单侧）
- **障碍物每轮随机摆放**（线的任意一侧）→ 绕障逻辑必须能自动判侧
- **两个 HC-SR04 必须分时触发**：同时发波会收到对方的回波（串扰）→ 各自独立 Trig 引脚 + 软件串行触发，两次测距至少间隔 60ms（等上一发余波衰减）
- **HC-SR04 的 Echo 是 5V 输出**：STM32F103 的 PA/PB 多数是 FT（5V 容忍）脚，仍建议串 1k + 2k/3.3k 分压（或 3.3V 钳位二极管），防上电瞬态与走线串扰
- **超声波看不到细柱**：HC-SR04 波束角约 15°，对细杆（光电门立柱、障碍物边缘）回波弱 → 起终点附近必须设禁避障区，避障判定加连续帧确认

### MCU 与引脚（第 3 周新增）
- **关掉 JTAG 可多出 3 个 IO**（PB3/PB4/PA15）：只用 SWD 调试时关掉 JTAG 即可；代价是**必须把 NRST 引到调试排针**，否则一旦程序跑飞或关闭 JTAG 的时机不当，就只能靠 BOOT0 跳线救板
- **PA11/PA12 是板载 USB 的 DM/DP**：部分克隆板在 PA12 上有 1.5k 上拉电阻 → 用作普通 IO 前要核对板型/丝印（本项目不用板载 USB，PA12 只作输出、PA11 拿去做 STBY）
- **PC13/PC14/PC15 驱动能力弱且不耐 5V**（只能小电流输出、不可作 5V 输入）→ 只放 LED 或作输入用
- **TB6612 的 AIN/BIN/STBY 要加 10k 下拉**：MCU 复位期间引脚是高阻，无下拉时电机可能被干扰误动 → 硬件下拉 + STBY 保留跳线可强制使能

### I²C 与供电（第 3 周新增，最容易烧器件）
- **灰度模块的板载上拉是 5V（10k）**（感为手册原文）→ 若把 3.3V 器件（SSD1306 OLED、MPU6050）挂到同一条总线上，**SDA/SCL 会被拉到 5V，超过它们约 3.6V 的极限，会烧** → 本项目把两条总线拆开：I2C1（灰度，5V 上拉）与 I2C2（OLED+MPU6050，3.3V 上拉）**绝不并联**
- **STM32F103 的 PB8/PB9 是 FT（5V 容忍）脚**，open-drain 模式下允许总线上拉到 5V → 跟 5V 传感器通信没问题；但**不可把 5V 上拉总线接到任何非 FT 脚**
- **一个 I²C 总线上只允许一处上拉源**：板载有上拉时 PCB 不要再并 3.3V 上拉，否则等效上拉变成高压侧，仍会打坏低压器件
- **专用电机排线里混着编码器信号**：JGB37-520 的 6 芯线同时走 M+/M−（2A 级、PWM 开关）与编码器 A/B/VCC/GND → 噪声耦合会丢计数；应对：A/B 串 100Ω + 并 1nF，编码器 VCC 就近 100nF，固件再做“最大跳变”过滤
- **电机侧连接器选型要注意额定电流**：JST-XH 触点约 3A，而 JGB37-520 堆转可到 2A+ → 堆转不要久留，否则座子发热
- **核心板自带 LDO（RT9193）与自备 LDO 不能同时对打**：5V 脚与 3V3 脚只能接一个；本项目只送 5V，3.3V 由核心板输出（≤300mA，需核算负载）

### 机械
- "3D 打印车架太轻会跑得快"是误解：速度由电机 + 轮径决定；轻的收益是加速与惯性，风险在强度/打滑
- 尺寸红线 250×200×200：旧车（大轮 + 铝方管）目测已接近上限，新设计必须实测旧车作为基线
- 中心设备（3D 打印/激光切割）可能要排队 → 模型尽早冻结并预约

### 工具与脚本
- **Windows 批处理（.bat）不能存成 UTF-8**：含中文的 UTF-8 .bat 会让 cmd 解析器错位（报「命令语法不正确」或把半行中文当命令执行）→ 必须存成 GBK 编码 + CRLF 换行
- **控制台代码页与 git 输出冲突**：git 输出是 UTF-8，中文 Windows 控制台默认 GBK（936），直接显示会让中文文件名/提交信息乱码 → 在 git 命令前后临时 `chcp 65001` / `chcp 936` 切换（脚本已内置）
- **用 `for /f` 抓取 git 配置时要先切 65001**：cmd 变量内部是 Unicode，抓取时按当时代码页解码；936 下抓 UTF-8 输出会导致中文被「双重转换」变成乱码（显示正常但内容是错的）
- **`git reset --hard` 会删掉“已 git add 但未提交”的新文件**（未 add 的 `??` 文件则会保留）→ 想做“只还原不删新文件”的工具，必须先在 reset 前执行 `git reset -q` 取消暂存
- **批处理文件的换行符必须统一成 CRLF**：混用（例如补丁只给新增部分写了 LF）会让 cmd 解析错位，报出一堆“xx 不是内部或外部命令”的碎片错误 → 每次改完 .bat 都要检查
- **测试 .bat 时注意两类假象**：①测试脚本若未提交，会被 `git clean -fd` 删掉导致 cmd 读串；②测试脚本若是“已修改的跟踪文件”，会被 `reset --hard` 中途还原导致同样问题 → 正确做法：把“输入已固定”的测试脚本提交并推送到沙盒远端，保证与远端一致
- **PlatformIO + stm32cube 框架（无 CubeMX 生成的 `it.c`）必须自己写 `SysTick_Handler`**：`HAL_Init()` 会开 SysTick 中断做毫秒计时，缺处理函数就跳进“默认处理器”的死循环——现象是 **LED 不闪、串口无输出、像死机**，但用调试器看会发现时钟/UART 寄存器都已正确初始化。排查捷径：`openocd` 里 `reg xpsr`，IPSR（低 9 位）= 15 即卡在 SysTick
- **读串口的脚本不要写 `while True: readline()`**：小车 100Hz 持续输出时永远读不完 → 用“限时循环”或设行数上限
- **PlatformIO 首次编译要联网**：会自动下载工具链与框架（约 200MB，国内需代理，5~15 分钟）；之后的增量编译只要几秒
- **`printf` 打印浮点要加链接参数** `-Wl,-u,_printf_float`（否则 `%f` 输出空或错乱）
- **HAL 的 `HAL_xxx_MspInit` 不能加 `static`**（HAL 头文件里是非静态声明，加了会编译报错）
- **自动化测试 `set /p` 的三个坑**：①**批量送入**（管道 / 重定向 / SendKeys 瞬时连发）会被 `set /p` 当“整行”读走，只有真实逐字键盘输入才按行读；②喂给重定向的输入文件**必须是 CRLF**，LF-only 会让第一行把后续内容全吃掉；③**`chcp 65001` 执行过后，重定向 stdin 下的 `set /p` 一律读到空**（真实控制台键盘输入不受影响）→ 测试交互脚本时先用无 `chcp` 的逻辑副本验证分支，再用真实控制台冒烟
- **`.bat` 里中文 `echo` 不能放在 `chcp 65001` 与 `chcp 936` 之间**：脚本本身是 GBK，控制台处于 UTF-8 时会显示成乱码 → 只让 git 输出留在 65001 段内，中文提示一律放在段外
- **“拉取并提交”合在一个脚本里是设计缺陷**（2026-09-13 修正）：它诱导“先改再拉”，一旦别人也改了同一处就会撞车 → 拆成「拉取.bat」（开工前）+「提交.bat」（收工时），顺序直接由脚本名固定下来；并把“已拉取？”做成 `提交.bat` 里的确认页（拉取 → 放入 → 提交），把提醒做进流程而不是只写在文档里
- **ChatGPT 的 GitHub 连接器是“用户级授权”，协作者也能读**（2026-09-13 实测）：一度以为“只有仓库所有者能用”——那是 GitHub App **安装**的规则（只能装到自己名下的账号）；这个连接器不走安装，GitHub 侧显示在 `Settings → Applications → Authorized GitHub Apps` 里的 `ChatGPT Codex Connector`（Owned by openai），而 `Installed GitHub Apps` 里是空的 → 访问范围 = **你自己 GitHub 账号对仓库的权限**，所以仓库协作者在自己的 ChatGPT 里连接自己的账号即可读。坑点：一直在找“选仓库 / Configure”是白找
- **测试建议**：脚本改动后用「固定值替换输入」的方式在沙盒仓库（裸仓库 + 克隆）里跑完整流程，比真实键盘更可控
- **LaTeX `standalone` 类在 xelatex 下不会自动裁边**：页面仍是 letter 尺寸，**长图会被截掉尾部**（本项目第一版接线图就丢了最后一栏）→ 用 `preview` 宏包（`\usepackage[active,tightpage]{preview}` + `\PreviewEnvironment{circuitikz}`）把页面设成内容尺寸；但 **`preview` 与 `standalone` 同时加载会产出 15 字节的空 PDF**，两个只能留一个
- **xelatex 输出中文要 xeCJK + 系统字体**（`\setCJKmainfont{Microsoft YaHei}`）；编译必须在 **ASCII 路径**的临时目录里做（中文路径下 pdftoppm / pdftotext 不稳，PowerShell 脚本也会被 cp936 误读）→ `hardware/原理图草案/生成接线图.py` 就是这么做的
- **circuitikz 的 `node[pmos]` 默认是竖放的**，旋转后锚点跟着转，直接接 `(Q1.D)/(Q1.S)` 会接出一团乱线 → 评审图里改用「模块框 + 文字」表示未定器件
- **画原理图前先给版面定约定再落坐标**：本项目电源图把 12V/5V/3.3V/接地四条母线各占一条 y，并规定「12V 支路下拉全部落在 x ≤ 16.6、5V 支路落在 x ∈ [22,24]」，于是全图可证不相交——比事后靠肉眼找交叉省事得多

### 分工与流程（演进史）
- 工作包体系：W1~W10（初版）→ W6 感知方案合并进硬件、W9 测试场地取消（现有复刻场地，不必自建）→ 增加 PCB 独立包 → D1 测试组织被删除（改由调试者自行组织）→ 最终定型 **M/H/A/P/D/F/S 七类 13 项任务**
- 分工方式：按人分工（初版）→ 按工作包列出特点供认领（最终采用）
- 目录命名：曾讨论把 `firmware/hardware/mech/tools/docs` 全改中文 → 决定暂不改（代码目录对编译工具链有中文路径风险，且改名要动多处引用）
- 曾出现"引脚分配方向含糊"（H 等 P、P 等 H）与"M01 与 H02 互等"两处依赖问题 → 用《引脚分配表》单向化 + PCB 对接约定冻结解决
- **硬件改为「原理图 → 面包板 demo → 布板下单」**（2026-09-20）：驱动离开实物写不踏实（PWM/编码器/超声波没法冒烟）→ 先用面包板把能验的信号级项目过一遍（双 I2C 电平、Echo 分压、串扰、线序），问题在打板前发现；布板与验证并行，下单仍按 9/30 节前窗口，冒烟有问题最晚 10/3 改板重下。代价：引脚表冻结从 9/24 挪到 9/28（首轮验证后）
- **任务清单改为“只写已完成与接下来谁做什么”**（2026-09-20）：去掉解释性旁白与“某某不做这个”式口径（它们只是内部变更的残留，对读者无意义）
- 《安装接口契约》（李昕程单方面出、要求过细）→ 精简为 **《车架与 PCB 对接约定》**（王政淋＋李昕程 一起定、熊雅琦辅助；只写对方必须知道的尺寸与孔位，细节两人自定），定稿期 9/24（2026-09-20 起）
- 调试曾被考虑为独立岗位 → 结论：**调试与算法强耦合，必须同一人/同场完成**，D1 岗位随之取消

### 硬件与方案
- 连接方案演进：全杜邦（初版）→ 误以为全换 XT/T 插（纠正）→ **按电流分级**（电池 XT、信号 XH/PH 带扣、不拆装焊死、调试留杜邦）
- 车架方案候选：整体 3D 打印 / 铝方管 + 板材 + 3D 打印件（旧车路线，较成熟）/ 木板 + 热熔胶（快速原型）→ 待 M01 定案；必要时可先做快速原型供电控联调
- 避障传感器候选：超声波（便宜、不受光影响、但角度窄有盲区）/ ToF 激光（抗光好、精度高、稍贵）/ 红外避障（受光影响大，不推荐）→ **9/20 定案：HC-SR04 超声波 ×2（左右各 1）**，理由是便宜、不受环境光影响；代价是盲区大、与光电门可能互相干扰（见 §4 传感器与环境）
- 芯片方案：曾讨论是否换芯片 → 结论：STM32F103C8T6 现有 3 块、性能足够（64KB Flash/20KB RAM），沿用
- 调试方式认知：曾设想"人工描述现象让 agent 直接调" → 明确**前提是遥测链路**，否则是盲猜 → P01 反馈链路因此前置到抢跑期
