# v8_2026-10-01_P01 精停加两道闸（窄线武装 + 里程门槛）

- 存档：2026-10-01 晚 · P01 · 基于 v7

## 起因：桌面测试"车自己进精停、界面看着像卡死"

用户跑车时发现数据"卡住"、事件里冒出 `FINISH TIMEOUT`。查下来是一条因果链：

```
车在灰色地板上被推着滚 → 灰度看到 1~7 路黑（被当成"窄线"）→ 攒够 1.5s ⇒ 武装 ✗
                      → 再遇到全黑（灰地板/阴影）⇒ **误判成终点线** ✗
                      → 进精停：电机停、画面上所有值不再变化 ⇒ 看着像卡死 ✗
```
> 注意：`Log_Stop()` 只停板载快照、**不停蓝牙**（数据其实还在流 ✗）——
> 是"车停了且所有值不变"看起来像卡死 ✓

## 两道闸

| 闸 | 做法 | 依据 |
|---|---|---|
| ① **只在真窄线上武装** | 累计条件从 `cnt > 0` 改成 `1 <= cnt <= 3` | 场地实测巡线时黑的是 **1~2 路**（43%/47%），**3 路及以上只占 0.1%** ⇒ 宽黑不是"跟线" |
| ② **里程门槛** | 新建里程计 `s_odo_cnt`（编码器计数绝对值），里程 < `TR_FIN_MIN_MM`(800mm) 绝不当终点 | 桌面推几把只有几百 mm；真赛道至少要跑 1.5m 以上 ⇒ 桌面永远进不了精停 |

另外：`else` 分支把"全黑但不认"分成了两种事件（限流 2s）——
`$E 83 START T ignored`（没武装）／`$E 84 FIN gated: too short`（有武装但里程不够）✓ 便于事后复盘。

## 实测

- 桌面连续 **55 秒**（旧版约 10 秒就误判）：**0 次 FINISH** ✓ 事件只有 `83` ✓
- 真赛道效果 **待场地实测**（本次只验证了"不再误判" ✓；能否在真终点正确触发要上车跑 ✓）
