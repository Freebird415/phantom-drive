> **本版最重要的一条：精停（终点停车）此前从未触发过** ✗
> 用户反馈“终点停车失败、沿着 T 头拐过去了”，查日志发现整趟 **没有一次 state=4**，
> 而当时 8 路全黑已经持续了 **8 秒（268 帧）** 也没反应 ⇒ 一定是逻辑问题。

## ① ⭐⭐ 精停锁存修复（关键）

自找的 bug（v3 重排顺序时引入）：
```c
if (cnt >= 8) { s_track_ms = 0u; }                    // 遇全黑先清零 ✗
else if (...) { s_track_ms += 10u; }                  // 累计“在线上跑的时间”
...
if (s_fin_need >= 3 && s_fin == 0u) {
    if (s_track_ms >= TR_FIN_ARM_MS) { 精停 }         // 却拿刚被清零的值判断 ⇒ 永远为假 ✗✗
```
⇒ **“武装”判断在全黑的同一拍里先被清零、再被检查** ⇒ **精停不可能触发** ✗

修法：改用**锁存标志** `s_fin_armed`（在线上跑够 1.5s 置 1；只有 `Trace_StartRun()` 新一趟才清 0 ✓），
黑条不再能清掉它 ✓

## ② 宽黑区放宽 + 出来后保持直行

日志逐帧证据（终点 T 头出口）：
```

2655  01010111 (5路黑) err=0    ✓

2658  00000001 (1路黑) err=3.5  pwm=38/-16  ✗ 当成“线在最右”⇒ 猛拐
```

- `TR_WIDE_BLACK_N` **5 → 3**（实测巡线时 3 路黑只占 0.1%，安全 ✓）
- 新增 **`TR_WIDE_HOLD_MS=300`**：黑区内 + 离开后 300ms 内**一律直行**（车过 T 头时常是斜的，
  退出的那几帧会出现“只剩边上一路黑”的假 err ✗）
