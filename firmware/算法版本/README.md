## 二、怎么切换 / 存档

```bash
python tools/algo_version.py list              # 列出版本（含当前生效版与 git 溯源）
python tools/algo_version.py use v2            # 切到 v2（会把当前文件先自动备份）
python tools/algo_version.py save "v4_降速保稳"  # 把当前 app_trace.c 存成新版本
python tools/algo_version.py diff v2           # 当前 vs v2 的差异摘要
```
> 手动也行：`cp firmware/算法版本/<版本>/app_trace.c firmware/src/app/app_trace.c`
> 切完**必须重新编译烧录**：`pio run -d firmware -t upload`

## 三、加新版本的规矩

1. 改 `firmware/src/app/app_trace.c` → 上车实测 → 觉得值得留存，再 `save`
2. 版本目录里补 `说明.md`：**改了什么 / 为什么 / 实测结果（链接到 `logs/共享_*.md`）**
3. 实测时用「蓝牙日志.bat」记录并生成共享摘要 ⇒ 版本和成绩一一对应 ✓
4. 命名：`v<序号>_<日期>_<作者>_<一句话>`（例 `v4_2026-10-02_A01_降速保稳`）

## 四、什么时候可以删旧版本

- 已被新版本**全面取代**、且结论已写进 `项目记录/经验与踩坑.md` / 共享日志 ⇒ 可以删 ✓
- 留着也有成本：每个版本几百行，不影响编译但会让“现在的策略是什么”变模糊
- 删之前确认：它的**教训**有没有被记录（没记录就先记，再删）

## 五、和 git 的关系

- git 是**完整历史**（每次提交都能回溯）✓
- 本目录是**可读的索引**：文件名带作者/日期/一句话，配 `说明.md` 和日志链接 ⇒ 不用翻 diff ✓
- 两者互补：git 保底、本目录好用 ✓
