# logs/ —— 本机详细数据 + 可分享的摘要（同一个文件夹）

> **2026-10-01 起采用“单文件夹 + 只放行某类文件”方案**（用户建议）：
> 不用在 `logs/` 和另一个共享目录之间来回看 —— 摘要就躺在数据旁边 ✓
> 靠本目录的 `.gitignore` 控制：**只有 `共享_*.md` 与 `README.md` 入库** ✓

---

## 一、两类东西

| | 例子 | 大小 | 入库？ |
|---|---|---|---|
| **本机详细数据** | `2026-10-01_1551_BLE实时/`（母日志）、`.../片段_xxx/`（子片段，含 `telemetry.csv`、`derived.csv`、`note.md`、`markers.txt`）| 几百 KB ~ 几 MB | ❌ **不入库**（`.gitignore` 拦掉）|
| **可分享摘要** | `共享_2026-10-01_P01_场地首测基线.md` | 3~6 KB | ✅ 入库 |

> 判据很简单：**共享的摘要一律以 `共享_` 开头** ✓；其他一律本地 ✓

## 二、摘要（`共享_*.md`）怎么产生

| 方式 | 操作 |
|---|---|
| **默认自动**（推荐）| 用「`蓝牙日志.bat`」：**每次停止记录后自动生成一份**；导出片段时也会自动生成 ✓ |
| 手动 | 点窗口里的「**分享到共享日志…**」（可改标题/记录者/结论）|
| 命令行 | `python tools/shared_log.py <日志目录> --name 2026-10-01_A01-熊雅琦_提速版 --who 熊雅琦 --commit fd83173` |

摘要里已经自动带上：来源信息、**汇总统计**（帧数/时长/里程/速度/偏差/两条通道累计转角/gz 是否在报数/state 分布）、
**ASCII 曲线速览**、关键帧、以及“读这份数据要知道的三件事” ✓

## 三、标题命名规范（必须）

```
共享_<日期>_<任务号-姓名>_<做了什么/哪一版>.md
例：共享_2026-10-01_A01-熊雅琦_提速版第一轮.md
    共享_2026-10-01_P01-李沛阳_场地首测基线(修复前).md
```
- 别用默认的 `BLE实时` ✗（事后分不清是谁哪一版）
- 任务号 + 姓名：别人一眼知道该找谁（`A01-熊雅琦` / `A02-毕烨恺` / `P01-李沛阳` …）

## 四、写完之后（很重要）

1. **「结论 / 观察」一节自己填** —— 现象、和上一版比哪里好/差、下一步想试什么。
   自动生成的数字谁都能算，**判断只有你有** ✓ 这段是整份摘要最值钱的部分。
2. 提交：`日志: <标题>`（或 `docs: 共享日志 <标题>`）✓
3. 原始 CSV **不要**提交（`.gitignore` 已拦 ✓）；要给别人细节，把整个目录单独发（微信/网盘）✓

## 五、别人（或 AI）怎么用

- 直接说「读 `logs/共享_2026-10-01_A01-熊雅琦_提速版第一轮.md`」✓
- 需要更深：按摘要里「本地完整数据」那行的路径，找记录者要目录，然后
  `python tools/plot.py <目录>` 出图 / 读 `derived.csv`（已算好的派生量）✓

## 六、体积纪律

- 单份摘要 **~10KB 以内**（生成器已经是这个量级 ✓）
- 别把 PNG/视频/CSV 拖进来 ✗
- 偶尔看一眼：`git count-objects -vH`；异常膨胀就在群里提 ✓

## 八、🔒 只读防护（2026-10-01 起）

数据文件（`telemetry.csv` / `derived.csv` / `meta.json` / `note.md` / `markers.txt`）
在**记录/导出结束时会被自动设成“只读”** ✓：

- 好处：任何"手滑写一下"（比如 shell 里 `>` 重定向、脚本误写）**直接失败** ✗ —— 真实数据只此一份，没有远端备份
- 要删：用图形界面的「丢弃本次日志」或「打开日志…→删除」✓（它们会先解除属性再删）
- 要改：先在资源管理器里取消"只读"属性（多一步，但这是刻意的 ✓）
